# Android Device UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the supplied `music.xima` icon and name, then make the existing swipe interactions and layout reliable on Android phones and tablets.

**Architecture:** Branding stays in Tauri-generated bundle resources. Gesture recognition remains a small framework-independent TypeScript helper used by the mini and full players. Shared viewport and width constraints stay in the existing app shell and UI primitives so feature screens do not duplicate responsive rules.

**Tech Stack:** Tauri 2.11, Android resources, SolidJS 1.9, TypeScript 5.9 strict, Tailwind CSS v4, HeroUI styles.

## Global Constraints

- Preserve the existing dark visual language and bottom navigation.
- Do not add a tablet-specific navigation system or redesign feature screens.
- Do not add dependencies or custom colors.
- Keep the product name exactly `music.xima`.
- Preserve the current gesture meanings.

### Task 2: Deterministic swipe recognition

**Files:**
- Modify: `src/features/player/model/gestures.ts`
- Modify: `src/features/player/ui/MiniPlayer.tsx`
- Modify: `src/features/player/ui/FullPlayer.tsx`

**Interfaces:**
- Consumes: existing `SwipeOptions`, touch start/move/end/cancel events, and `data-no-swipe` controls.
- Produces: the same `SwipeHandlers` API with dominant-axis locking and deliberate-distance recognition.

- [ ] **Step 1: Add dominant-axis locking**

In `createSwipe`, track an axis state of `'pending' | 'horizontal' | 'vertical'`, wait for an 8px slop, choose the axis only when the dominant delta is at least 1.15 times the other delta, and reset all state in `finish()`.

- [ ] **Step 2: Restrict live feedback to the locked axis**

Call `onMove` only after the axis is locked, zeroing the non-dominant delta. Keep the existing 60px default and 90px full-player threshold.

- [ ] **Step 3: Make gesture surfaces explicit**

Apply `touch-none` to the fixed mini-player and fullscreen player content. Preserve `data-no-swipe` on the seek bar and player controls so taps remain independent.

- [ ] **Step 4: Type-check gesture consumers**

Run: `npm run typecheck`

Expected: exit 0 with no TypeScript diagnostics.

### Task 3: Phone and tablet viewport behavior

**Files:**
- Modify: `src/styles/index.css`
- Modify: `src/app/App.tsx`
- Modify: `src/app/BottomNav.tsx`
- Modify: `src/shared/ui/Screen.tsx`
- Modify: `src/features/player/ui/MiniPlayer.tsx`
- Modify: `src/features/player/ui/FullPlayer.tsx`

**Interfaces:**
- Consumes: existing safe-area tokens and `Screen` primitive.
- Produces: a dynamic-height app shell, tablet-readable screen width, and a centered fullscreen-player workspace on wide screens.

- [ ] **Step 1: Harden the root viewport**

Set `html`, `body`, and `#root` to `height: 100%`, `min-height: 100dvh`, and `overflow: hidden`; keep safe-area and overscroll rules.

- [ ] **Step 2: Respect reduced motion**

Add a `prefers-reduced-motion: reduce` base rule that reduces animation and transition durations without removing functional state changes.

- [ ] **Step 3: Constrain screen content on tablets**

Add `mx-auto max-w-3xl` to the shared `Screen` root and to the inner mini-player/navigation rows so content and controls remain readable while their dock backgrounds stay full-width.

- [ ] **Step 4: Size the app shell and full player dynamically**

Use `h-dvh` on the app shell. Center the full-player dialog and cap it at `max-w-2xl` on tablet widths while retaining full width on phones and square artwork sizing.

- [ ] **Step 5: Run frontend verification**

Run: `npm run build`

Expected: TypeScript and Vite both exit 0.
